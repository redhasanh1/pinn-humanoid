PINN Brain Stack

Five layers of compute, each doing only what it is fast enough for. Reflexes never wait for the network, the robot's own chip does the seeing, a rented GPU checks plans against physics, the cloud does the thinking, and overnight the robot "dreams" so it wakes up better without any training.

Hardware picks and prices from Kimi (senior build manager, web search, 27 Sep 2026). Speeds on the robot chip are estimates until we measure them. The 1,024-grasp physics number is our own measurement.

What nobody else is doing

Idea 1

Surprise-budgeted attention

The robot only pays for big compute when the world surprises it: the change detector fires, or what it sees doesn't match what it expected. Routine scenes run on free local habits. The capstone graph: cloud calls per task vs success rate, with the surprise threshold as the dial.

Idea 2

Physics oracle

Before a risky grasp, a rented GPU replays it in 1,024 slightly different worlds and returns a real probability of success. Most robots guess; this one checks. We already measured 1,024 grasp candidates in 1.9 s on the 1660 Ti; a 4090 does it in about 0.2 s.

Idea 3

Dream mode

Overnight, one cheap GPU hour replays the day's objects and writes the lessons into the robot's habit memory. Dreamer-style robots retrain their weights; ours changes no weights at all. It just wakes up remembering which grasps are fragile. The graph: yesterday's objects, success before vs after dreaming.

Build order

  1. Now, free: run the robot-brain tier on the laptop with the InnoMaker camera. Measure real fps.
  2. Buy the Jetson Orin Nano Super and move that tier onto it, on the robot.
  3. Surprise meter: wire the existing change detector and expectation checks into one score that decides when to call the cloud.
  4. Physics oracle: a small API on a rented 4090 that takes a scene + grasp and returns the best grasp and its probability. Advisory only.
  5. Dream mode: a nightly job that uploads the day's objects, runs the oracle in batch, and writes the results into habit memory.
  6. Measure: cloud calls per task, and grasp success before vs after a night of dreaming.

What can go wrong

Wi-Fi jitter: nothing past the robot chip is ever allowed in the reflex path. The oracle and the cloud are advisory; if they're late, the robot keeps its current plan.
Rented GPUs can vanish mid-session: the robot must run fine without them.
The oracle is only as right as our physics model: if the finger/tendon model is wrong, it returns confident nonsense. Keep testing the sim against the real hands.
Too early for the oracle: sim grasps already succeed 92–98%. The oracle earns its cost once real grasps start failing on real objects, not before.
